# Tasks: receipt-viewer

Each task writes its test first (`test/site-<module>.test.js`), runs it and sees it fail, then writes the implementation and
runs `npm test`. Tests never touch the network: fetch is injected.

Contracts: the gate runs every frozen contract on every tick and refuses to tick an unfrozen spec. So a task that covers
acceptance criteria also adds `contracts/receipt-viewer/<module>.contract.test.js` with one test per criterion, named
`R<req>.<n> <behavior>` (for example `R3.2 page and CLI compute the same receipt hash`). The agent writes the contract
from the criteria, then stops before ticking the task. A person reviews it and runs `necro freeze receipt-viewer`. After
that the tick runs the gate. The agent never edits a frozen contract or `requirements.md`.

Do not change anything under `src/`. The viewer reads from it in tests only.
