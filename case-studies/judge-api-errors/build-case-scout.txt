**1. The dry run coerces bad input instead of rejecting it** (`src/evaluate.js:23-30`, highest value)
- **Input:** `dryRunEvaluate({criteria, deliverable: {a:1}})` hashes the string `"[object Object]"`. `deliverable: null` hashes `"null"`.
- **Input:** `deliverableBase64: "***"` decodes to an empty buffer. A `length` check with `max: 10` then passes.
- **Input:** `jobId: "007"` goes into the hash as `"007"`, not `"7"`. The route promises "exactly the evidenceHash a real run would produce", and this one can't match.
- **Test gap:** `test/evaluate.test.js` covers neither case.
- **Acceptance criteria:**
  - WHEN `deliverable` is not a string, THE SYSTEM SHALL return 400.
  - WHEN `deliverableBase64` contains non-base64 characters or malformed padding, THE SYSTEM SHALL return 400.
  - WHEN `jobId` has leading zeros, THE SYSTEM SHALL reject it or normalize it before hashing.

**2. `/verdict` returns raw RPC error text in a 500** (`src/http.js:145`)
- **Input:** a `publicClient.readContract` stub that throws `new Error("URL: https://rpc.example/KEY")`. The response body then contains that URL.
- **Why it matters:** viem's error messages include the RPC URL, and `ARC_RPC_URL` may carry an API key.
- **Related:** `new URL(req.url, …)` on a bad target such as `//` throws inside the same `try`, so it also gets a 500 instead of a 400.
- **Acceptance criteria:**
  - WHEN an upstream RPC call fails, THE SYSTEM SHALL return 502 with a fixed message that contains no URL or request body.
  - WHEN the RPC call fails, THE SYSTEM SHALL log the full error server-side.
  - WHEN the request target cannot be parsed, THE SYSTEM SHALL return 400.

**3. The `length` check's `chars` unit counts UTF-16 units** (`src/checkers/index.js:113`)
- **Input:** `{kind:"length", params:{min:1,max:1,unit:"chars"}}` against `"😀"`. `text.length` is 2, so the check fails.
- **Inconsistency:** `json-shape.js` counts code points specifically so every implementation gives the same answer. This check doesn't. Its copy in `web/app.js` is the first place divergence would show up.
- **Docs:** I found no definition of `chars` in the workspace, so confirm the intended unit first.
- **Acceptance criteria:**
  - WHEN `unit` is `chars`, THE SYSTEM SHALL count Unicode code points, not UTF-16 units.
  - WHEN the deliverable contains a surrogate pair, THE SYSTEM SHALL count it as one character.
  - WHEN `unit` is `words`, THE SYSTEM SHALL keep its current counting.
