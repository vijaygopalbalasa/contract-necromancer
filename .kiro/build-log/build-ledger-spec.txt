I wrote `.kiro/specs/ledger/design.md` and `.kiro/specs/ledger/tasks.md` and left `requirements.md` unchanged. There are 8 tasks, each with its tests first. Together they cover every acceptance criterion from 1.1 through 4.3. I stopped here, so no code or tests exist yet.

The design splits the work into small pure modules under `src/`: errors, money, parse, split, balances, settle and report. `bin/ledger.js` only parses arguments, reads the file and prints, as the tech steering requires.

- **Fewest payments:** The product steering says "fewest payments", but Req 3.2 fixes a greedy rule. That rule is deterministic and uses at most N−1 payments, but it isn't guaranteed to be the global minimum. I followed the requirement and noted this in the design.
- **Choices the requirements leave open:**
  - A wrong usage, such as a missing file argument, prints a usage sentence and exits 1.
  - Keywords `paid`, `for` and `split` are lowercase and case-sensitive.
  - Repeated names in one `split` list count once.
  - An empty entry such as `a,,b` is an error.
  - A file with no expenses prints `All square.`.
  - The balances table follows the order of first appearance.
