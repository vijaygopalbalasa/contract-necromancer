- **What the receipt records:** in a git repo, `uncommitted` is the sorted, unique list of pinned paths that differ from the file at the recorded commit, or that the commit lacks. Pinned paths are the requirements file, the contract files and the traced sources. The list is `[]` when every pinned file matches the commit.
- **How it compares:** each file's SHA-256 is checked against `git show <commit>:./<path>`. The `./` makes it work when the project root is a subdirectory of the repo, and one test covers that.
- **Determinism:** `uncommitted` is part of `receiptHash`, so the hash stays the same for identical inputs. A test also checks that editing the list changes the hash.

Decision for you: when there is no commit to compare against (not a git repo, or a repo with no commits), I leave `uncommitted` out. Writing `[]` there would claim the files match a commit that doesn't exist. Req 5.4 only covers git repositories, so this doesn't contradict it.
