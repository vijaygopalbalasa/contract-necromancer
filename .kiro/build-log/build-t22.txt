**How I read 6.9:** the project root is found from the receipt's location, not from where you run the command. `necro verify` starts at the receipt file's folder and walks upward to the nearest folder holding `.necro/lock.json`. That folder is the root for everything else: re-hashing pinned files, reading the lock and running the contracts. If no folder above the receipt has a lock, the current folder is used, as before. A relative receipt path is still resolved against the current folder.

The criterion's "from a folder that does not contain the receipt's project" could mean only applying the lookup when the current folder isn't already the project. I applied it always. When you run from the project root, the nearest lock is that root, so nothing changes there.

Run on the real `pumpkin-ledger` receipt, the current code gives `CONFIRMED` from the example folder and from `/tmp`. Before the change, the root and `/tmp` runs gave `MISMATCH`.
