**How I read the criterion**
- **Format:** I used the IDE 1.0 / CLI V3 format from Kiro's docs, which I read as raw markdown because the page itself renders client-side. That means `permissions.rules` with `capability`, `match` and `effect`, `file://` resources, and an inline `hooks` array.
- **Freeze patterns:** shell patterns only support `*`. "Every spelling a glob can express" therefore means one space between the necro word and `freeze`, with an optional closing quote. Extra spaces, `necro "freeze"` and `necro 'fr'eeze` can't be written as a glob. The hook from 3.14 still blocks those.
- **Over-matching:** the globs also deny harmless text such as `echo "necro freeze x"` and `mynecro freeze`. A glob can't tell those apart, and a deny only errs on the safe side.
- **`.necro/` writes:** the patterns are case-sensitive, so `.NECRO/` on a case-insensitive disk is left to the 3.5 hook check.
- **Validation covers the schema, not the engine:** the tests and `validate` check the file's shape and my glob reading, not how Kiro's permission engine enforces the rules. I did not run a live session. That includes whether `*` matches across newlines.
- **Hooks run twice:** if both `.kiro/hooks/necromancer.json` and the agent are active, each hook may fire twice. The handlers are idempotent, so this should be harmless.
