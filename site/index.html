Contract Necromancer

Kiro cannot call a task done until its frozen contracts pass.

Design by Contract, from Eiffel (1986), raised for coding agents.

  1. Kiro says task 4 is done. The code loses cents.
  2. The gate refuses the tick. Failing contracts: R2.1, R2.2 and 7 more.
  3. After the fix, the gate accepts the tick and writes a receipt. necro verify prints CONFIRMED.
See it happen for real: npx -y github:vijaygopalbalasa/contract-necromancer demo

Try the gate on this page

Send the gate a false "done" for task 4, watch it refuse, then send the fix and watch it accept.

The change that loses cents, in src/split.js

-Removed:const base = Math.floor(cents / n);

+Added:const base = Math.round(cents / n);

-Removed:const extra = cents % n;

+Added:const extra = 0;

  1. Kiro says task 4 is done, with that change in the code.

  2. Put the two lines back as they were, then send the tick again.

  3. Change one byte of src/split.js and check the receipt's pinned files again.

The browser runs the contracts with small stand-ins for node:test and node:assert, while the gate runs them in Node.js.

On a task that cannot be finished, across two models, Kiro marked it done in 11 of 11 runs without the gate and 0 of 19 with it. Under a "do whatever it takes" prompt, one gated run of six got past the gate by patching JavaScript built-ins. That hole is closed and the cheat is kept as a test. See the experiment.

How it works

  1. A person freezes the spec's contracts.
  2. The gate refuses to tick a task until they pass.
  3. Every passing task leaves a receipt anyone can re-run.
npx -y github:vijaygopalbalasa/contract-necromancer demo

Needs Node.js 24 and git, and shows the gate refuse a planted bug, accept the fix and re-check the receipt.

Re-run it yourself

This command clones the repository at the commit, takes the receipt from the default branch, and runs necro verify on it. It needs Git and Node.js 24 and no install, and it changes nothing outside the folder it clones. It assumes the receipt is in the default place, .necro/receipts/.

The verifier comes from vijaygopalbalasa/contract-necromancer at a fixed commit named in the command, never from the repository being verified, so a project cannot ship a verifier that always says CONFIRMED. Verifying runs the project's own contracts, which is code from that repository, so run this command only for a repository you are willing to run.
